# XHS-Chimera 产品需求与完整功能目录

> 状态：产品基线。任何功能规划、页面设计、数据模型和自动化能力都必须以本文的用户价值、任务链路和渐进暴露原则为准。
>
> 主仓库基础设施来源：Little-Red-Ant；它不是 XHS-Chimera 的产品主体。XHS-Chimera 从多个案例中吸收可复用的用户价值、交互模式、工作流和工程经验，形成独立产品。

## 1. 产品使命

XHS-Chimera 是一个本地优先的创作者内容经营系统，帮助个人创作者和小团队持续完成：

```text
发现真实用户需求
→ 判断哪些机会适合自己的账号
→ 制作可编辑、可发布、品牌一致的内容包
→ 审阅并由人确认发布
→ 获取数据和评论反馈
→ 将反馈转为下一轮内容与经营决策
```

它不以“尽可能自动发帖”为中心。AI、浏览器自动化、任务队列、模型配置、MCP 和数据抓取都是后台能力；用户前台应围绕内容任务和经营判断。

## 2. 用户与待解决问题

### 2.1 个人创作者

**实际问题**

- 打开多个工具后不知道今天应先做什么；
- 选题依赖刷热点或临时灵感，不知道目标用户真正需要什么；
- AI 文案结构正确但不像自己，无法使用；
- 文案、封面、配图、素材、数据和发布记录散落在不同工具；
- 内容做完即结束，没有系列、没有可复用经验。

**产品结果**

- 从“今天要做什么”开始；
- 得到有证据、有受众、有目标的内容机会；
- 得到可编辑的完整内容包；
- 每次发布后留下下一篇内容的线索。

### 2.2 小团队 / 工作室

**实际问题**

- 多账号内容、风格、素材和目标串号；
- 协作依赖聊天记录，草稿版本和最终发布版本不清楚；
- 发错账号、重复发、定时任务不透明；
- 数据回顾无法对应到内容来源、选题和负责人。

**产品结果**

- 账号、内容、素材、版本、审批和发布回执可追溯；
- 账号之间隔离，团队成员能明确看到任务状态；
- 高级团队能力按需求出现，不干扰个人创作者主路径。

### 2.3 品牌 / 业务型创作者

**实际问题**

- 热点流量与产品、服务、咨询目标脱节；
- 不知道评论里哪些是痛点、购买信号、异议或产品机会；
- 内容不能持续反哺产品、服务和用户理解。

**产品结果**

- 将内容与用户问题、咨询意图、产品机会和转化目标连接；
- 用证据辅助判断，不用“爆款评分”替代业务决策。

## 3. 产品交互原则

### 3.1 复杂度迁移 + 渐进暴露

产品不消灭任务本身的判断复杂度；产品承担理解界面、寻找入口、重复配置和机械操作的复杂度。

```text
默认路径
  → 高级设置 / 自定义
    → 工作流 / 自动化 / API / 专业能力
```

- 简单发生在路径上，不能通过删掉专业能力实现；
- 用户尚未产生需求时，不强迫用户理解底层概念；
- 高级功能必须可发现，并在对应任务阶段可进入；
- 用户熟练后，可以跳过新手路径、保存默认值和运行工作流；
- 涉及账号写入、批量分发和不可逆动作时，保留清楚的人类确认。

### 3.2 功能位置

```math
位置 \approx f(使用频率, 任务关键度, 理解成本)
```

| 功能特征 | 位置策略 |
|---|---|
| 高频 + 低理解成本 | 放在主任务页面 |
| 低频 + 高理解成本 | 放高级设置或专业工具区 |
| 高频 + 高理解成本 | 拆成向导、推荐、预设、分步确认 |
| 低频 + 低理解成本 | 上下文动作或次级菜单 |

### 3.3 系统与用户的职责

**系统负责**：关联资产、准备默认值、提示缺失信息、保留版本、计算重复和风险、组织流程、展示证据、执行可控的机械步骤。

**用户负责**：确定账号目标、确认真实性、选择内容角度、审阅表达、决定是否发布、承担业务判断。

## 4. 默认主路径：首页 / 今日工作台

### 提供功能

首页只呈现三个主动作：

1. **找一个值得做的选题**
2. **继续完善一篇内容**
3. **查看已发布内容的反馈**

以及少量按当前上下文生成的卡片：

- 本周尚未覆盖的栏目；
- 最近频繁出现的用户问题；
- 待继续修改的草稿；
- 等待人工确认或人工处理的发布任务；
- 已发布内容中新出现的高价值追问；
- 账号目标相关的提醒，例如“本周尚无建立信任型内容”。

### 解决问题

避免用户先学习“账号矩阵、RPA、任务队列、模型 Provider、Cookie、MCP”等产品结构，才能开始做内容。

### 主路径结果

用户从一个清楚的“今天要完成什么”进入下一步，而不是从模块目录开始。

## 5. 账号经营档案

### 提供功能

每个账号维护一份动态经营档案：

- **经营目标**：涨粉、咨询、产品推广、专业信任、市场验证等；
- **目标用户**：身份、情境、困扰、常见误区、决策障碍；
- **账号独特素材**：真实经历、专业能力、案例、产品服务、可公开展示的证明；
- **内容栏目**：避坑、案例、实操、观点、产品答疑、系列教程等；
- **表达边界**：不做的主题、不能承诺的表达、价值观与法律/品牌限制；
- **声音与写作样本**：口吻、常用词、禁用语、历史优质文章；
- **视觉资产**：颜色、字体、封面结构、常用素材、人物/产品主体、模板；
- **内容地图**：已发布主题、正在连载的系列、待填补的主题空白；
- **账号健康信息**：登录状态、授权状态、最后数据同步时间。该信息只在用户要发布或管理账号时出现。

### 解决问题

- AI 每次都要重复解释“我是谁”；
- 内容风格和视觉不稳定；
- 账号越做越杂，没有栏目和连续性；
- 多账号之间串素材、串语气、串选题。

### 与其他模块联动

```text
账号档案
→ 过滤不适合的热点与需求
→ 内容机会匹配与排序
→ 文案风格、事实补充、视觉模板默认值
→ 发布账号校验
→ 栏目/系列复盘
```

## 6. 需求雷达

### 提供功能

用户输入关键词、赛道或业务问题后，系统组织公开笔记、评论、竞品内容、热点和自身数据，输出：

- 高频问题；
- 用户抱怨、愿望、害怕和反对意见；
- 用户原话及原始上下文；
- 常见误区；
- 内容供给缺口：讨论多、回答少或回答质量低的点；
- 竞品已覆盖角度、未覆盖角度和不可直接复制的专属经验；
- 讨论热度、评论密度、重复表达等信号；
- 与当前账号的匹配度和风险提示；
- 可转为内容、系列、产品/服务验证的机会。

### 解决问题

用户不缺“热点清单”，缺的是：谁在什么场景遇到什么问题、自己是否值得回答、回答后应该验证什么。

### 关键交互

- 初级用户只看到三到五个推荐机会及简洁理由；
- 点击“为什么推荐”才展开证据、筛选条件、评论、竞品和信号；
- 高级用户可定义数据源、时间区间、平台、互动阈值、排除条件、目标用户标签；
- 所有研究结果带来源链接、采集时间和可见的证据强度。

### 与其他模块联动

```text
需求雷达
→ 内容机会卡
→ 商业机会验证
→ 评论回复建议
→ 发布后复盘的下一篇内容建议
```

## 7. 内容机会卡

### 提供功能

需求雷达中的每个可行动机会可保存为内容机会卡，包含：

- 主题；
- 目标受众；
- 用户场景；
- 核心问题/痛点；
- 用户原话和证据；
- 当前账号的独特角度；
- 推荐内容形式：清单、案例、复盘、教程、观点、对比、问答；
- 预期作用：收藏、信任、讨论、咨询、转化、需求验证；
- 适用账号和栏目；
- 与已发布主题和内容系列的关系；
- 风险：证据不足、热点过期、与账号不匹配、与近期内容重复；
- 后续内容建议。

用户可：加入选题池、立即创作、暂缓、标记不适合、转为产品机会、归入栏目或系列。

### 解决问题

研究数据和选题常在不同页面，用户最后仍要自己从“评论、热门、趋势”推导“所以我该写什么”。

### 与其他模块联动

```text
证据包 → 内容机会卡 → 内容包 → 发布包 → 发布结果 → 新证据 / 新机会
```

## 8. 内容包与编辑器

### 提供功能

用户从内容机会卡创建的不是一段孤立 AI 文案，而是版本化内容包：

- 多种意图的标题：收藏型、案例型、冲突型、观点型；
- 正文结构：开头、核心论点、案例/步骤、结尾互动；
- 需要用户补充或核验的事实标记；
- 推荐标签及理由；
- 发布目的、适用账号、栏目和证据关联；
- 小红书图文分页结构；
- 每页视觉任务和文本密度建议；
- 封面方向；
- 发布前审结果；
- 版本历史和差异；
- 未来可派生的公众号长文、视频脚本、其他平台版本。

### 编辑体验

- 初级模式：直接编辑标题、正文、封面短标题、图片；
- 需要时展开“结构”“来源”“视觉计划”“版本差异”“跨平台适配”；
- 用户可要求 AI 改写一段、保留原意、强化案例、降低营销感、补充自己的经验，而不是一次性覆盖全文；
- 未经用户确认的事实、案例和承诺必须可见地标记。

### 解决问题

现有 AI 工具通常只交付“标题 + 正文 + 标签”，无法直接排版、无法保留用户真实经历、无法追踪最终版、无法衔接图文与发布。

## 9. 品牌视觉工坊

### 提供功能

- 品牌色、字体、封面结构、图片比例、留白和栏目模板；
- 固定人物、产品、吉祥物或视觉主体；
- 统一视觉样本和已确认模板；
- 从内容包生成封面方向、逐页视觉任务和分页卡片；
- 先生成一张样图，用户确认后才生成整套图文；
- 专业画布：文字层级、裁切、图片替换、位置调整、品牌元素、单页重做；
- 导出小红书图文、长图、公众号图片和可复用模板。

### 解决问题

- 每次 AI 出图风格随机；
- 封面文字不可读或缺少内容层级；
- 图文页、文案结构和视觉不匹配；
- 用户不会设计，又不愿完全放弃控制；
- 每篇内容都从零做视觉。

### 与其他模块联动

```text
账号视觉资产 + 内容包分页
→ 样图确认
→ 批量卡片/配图
→ 发布预览
→ 视觉效果复盘
```

## 10. 发布前审

### 提供功能

发布前展示简洁检查单：

- 账号、内容目标、草稿版本、素材数量和完整性；
- 标题、正文、图片、视频、话题是否匹配；
- 明显夸大、承诺、敏感表达、必要披露、事实证据不足；
- 与同账号近期内容的重复度；
- 账号身份、发布目标和发布包是否一致；
- 立即发布或定时发布；
- 最终发布预览；
- 风险提示、改写建议和用户忽略理由。

用户可修改、保存草稿、查看详细解释、进入高级发布配置，或明确确认发布。

### 解决问题

用户担心发错账号、发错版本、漏素材、表达有风险、预览与实际不一致、未知结果下重复发。

### 边界

审查功能只提示风险和依据，不承诺平台审核结果，不提供规避审核的技巧。

## 11. 发布与任务中心

### 提供功能

任务中心展示真实状态而非模糊加载：

```text
草稿 v3
→ 发布前审通过
→ 等待人工确认
→ 已进入账号队列
→ 浏览器已打开
→ 素材上传中
→ 表单填写中
→ 等待平台回执
→ 已确认发布 / 需要人工处理 / 发布失败
```

- 每账号任务排队和身份校验；
- 多账号分发时分别显示每个账号的结果；
- 相同内容幂等去重；
- 登录失效、账号不匹配、验证码、安全验证时停止并保留现场；
- 未确认成功标为“需要检查”，禁止盲目自动重发；
- 查看发布使用的内容版本、素材、账号、日志和截图；
- 任务可取消、暂停、重新审阅；
- 高级用户可配置排期和工作流，但默认不暴露浏览器/RPA 细节。

### 解决问题

避免“点击发布 → 页面卡住 → 不知道是否成功 → 再点一次 → 重复发布”的黑箱体验。

### 当前已落地的基础能力

- 三层人工确认约束（前端、API schema、任务执行器）；
- 账号级发布互斥；
- SQLite 持久化幂等；
- 明确成功、未知提交、验证码/人工处理、失败的状态分离；
- 未知提交和人工审查状态不自动重试；
- 提交前异常允许有限重试。

## 12. 发布后复盘

### 提供功能

每个已发布内容关联：

- 当时账号目标；
- 内容机会和研究证据；
- 内容/视觉版本；
- 发布账号和时间；
- 初始及周期性指标；
- 评论中的高频问题、追问、异议、咨询和产品信号；
- 与栏目、系列和其他内容的比较；
- 可复用经验；
- 从评论和数据自动形成的新内容机会卡。

复盘回答：

- 这篇为什么有效或无效；
- 它是否吸引到目标用户；
- 哪个结构、标题、栏目或场景值得复用；
- 哪个评论问题值得做下一篇；
- 高互动是否真的符合账号长期目标；
- 是否形成咨询、产品兴趣或需求验证信号。

### 解决问题

避免只有“赞、藏、评”数字，没有下一步内容决策的复盘。

## 13. 熟练用户与团队能力

这些功能不占据初始主路径；用户产生对应需求时进入。

### 13.1 内容经营

- 多账号内容日历；
- 栏目与系列规划；
- 选题池排序和覆盖度；
- 内容模板、品牌模板、素材库；
- 跨平台派生版本；
- 自定义预审规则。

### 13.2 工作流与自动化

- 把“研究→选题→内容包→审阅”保存为工作流；
- 默认值、批处理、定时数据同步；
- 人工审核节点、负责人、交接和审批记录；
- MCP / API 接入；
- 外部内容源和模型 provider 的可插拔接入。

### 13.3 团队协作

- 内容负责人、编辑、审核者、发布者角色；
- 评论、修改建议、版本对比；
- 账号权限隔离；
- 资产和证据可追溯；
- 审核/发布操作审计。

## 14. 明确不做或受限做的能力

- 自动养号、自动点赞、自动评论、自动私信引流；
- 验证码绕过、浏览器指纹伪造、规避平台风控；
- 把未经证实的竞品经历、原文、图片直接复刻；
- 无人工确认的账户写入；
- 将热度分数或 AI 判断当作业务决策替代品；
- 仅因为架构完整而增加用户看不到价值的模块。

## 15. 功能验收问题

每一个功能进入产品前必须回答：

1. 用户在哪个任务阶段首次需要它？
2. 它替用户减少了哪一种具体无价值思考或重复操作？
3. 用户不理解它时，能否继续完成主任务？
4. 用户需要时，能否发现、理解、修改和撤销？
5. 它输出的是证据、建议、可编辑产物，还是越权替用户做判断？
6. 它与账号档案、内容机会、内容包、发布和反馈中的哪些对象关联？
7. 如何在不暴露底层基础设施的情况下让用户获得它的价值？
