# 常见扫码失败排查

扫码绑定是小红蚁使用频率最高的操作之一。本章汇总了最常见的失败场景、原因和解决方法。

---

## 一、二维码窗口一闪而过

### 现象

点击“绑定浏览”后，浏览器窗口弹出不到 1 秒就自动关闭，随后账号状态显示“可预览”或“未授权”。

![登录页面](../assets/screenshots/login-page.png)

### 根因

系统检测到浏览器中已存在旧 Cookie，并且误判为登录成功。常见情况：

1. 之前绑定过该账号，残留 Cookie 未清理。
2. 浏览器上下文复用了上一次扫码的部分状态。
3. 登录态判断逻辑误把非认证 Cookie 当作有效登录凭据。

### 解决方法

1. 在账号矩阵中找到该账号，点击 **清除 Cookie** 或 **重新绑定**。
2. 关闭小红蚁桌面端/浏览器，重新打开后再次扫码。
3. 检查后端日志，搜索 `Main site pre-check`，确认 `domLoggedIn` 和 `cookieLoggedIn` 是否同时为 `true`。

!!! note "已修复"
    当前版本已在预检失败后自动清理旧 Cookie，并采用 **DOM + Cookie 双重 AND 校验**，该问题已大幅减少。若仍复现，请反馈日志。

## 二、二维码一直不显示

### 现象

扫码窗口打开后，页面一直空白或显示“加载中”，没有二维码。

### 可能原因

| 原因 | 排查方法 | 解决 |
|---|---|---|
| 网络连接问题 | 后端日志出现 `net::ERR_CONNECTION_TIMED_OUT` | 检查网络，尝试切换代理 |
| 小红书反爬拦截 | 页面出现验证码或滑动验证 | 等待 5 分钟后重试，或更换 IP |
| Playwright 浏览器未安装 | 启动时提示 `Executable doesn't exist` | 运行 `npx playwright install chromium` |
|  headless 模式被识别 | 日志提示 `Anti-bot detected` | 系统已启用 stealth 插件，若仍失败请重启 |

## 三、已扫码但未返回成功

### 现象

手机已经扫码，但电脑端一直显示“等待扫码”，最后超时失败。

### 可能原因

1. **未点击确认登录**：只扫码不确认，系统拿不到 Cookie。
2. **扫码超时**：二维码有效期通常为 2~3 分钟，超时需重新生成。
3. **Cookie 获取失败**：确认登录后，小红书未返回 `web_session` 或 `websectoken`。

### 解决方法

1. 重新点击 **绑定浏览**，生成新二维码。
2. 扫码后**立即在手机上点击确认**。
3. 如果多次失败，查看后端日志中的 `Main Site Login verified!` 是否出现，以及是否打印 `missing auth cookies`。

---

## 四、状态显示“已过期”

### 现象

之前绑定成功的账号，突然显示 **已过期**。

### 根因

小红书 Cookie 过期，或账号在别处登录导致原 Cookie 失效。

### 解决方法

点击账号卡片上的 **重新绑定**，按 [绑定浏览权限](bind-preview.md) 流程重新扫码。

---

## 五、日志关键词速查

在排查问题时，可以在后端控制台搜索以下关键字：

| 关键字 | 含义 |
|---|---|
| `Main site pre-check` | 主站登录预检结果 |
| `QR code captured` | 二维码已成功截取 |
| `Main Site Login verified!` | 登录态验证通过 |
| `missing auth cookies` | Cookie 中缺少 `web_session`/`websectoken` |
| `Anti-bot detected` | 被小红书反爬拦截 |
| `COOKIE_EXPIRED` | 账号 Cookie 已过期 |

---

## 仍无法解决？

如果以上方法都无效，请准备以下信息并提交反馈：

1. 操作系统版本（Windows / macOS / Linux）
2. 小红蚁版本号
3. 后端日志中最近 50 行与扫码相关的输出
4. 是否使用了代理/VPN
5. 该账号是否能在手机 App 正常登录
